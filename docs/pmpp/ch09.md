- [x] 9.3 Latency and throughput of atomic operations
  - Modern GPUs support atomic operations in the last level cache, e.g. L2.
    The atomic operation read-modify-write mark the relevant L2 cache line
    dirty. That line will be written back to DRAM sometime later.

- [x] 9.4 Privatization
  - The idea is use a private histogram table per thread block to reduce
    atomic contention, then merge them after all blocks are done.
  - [Privatized][hist_private]: one `nBins` slice per block in global memory.

- [ ] 9.5 Coarsening
  - [Contiguous][hist_contiguous]: simple, intuitive, but, sub optimal GMEM
    access pattern, because each thread access elements far away from each
    other.
  - [Interleaved][hist_interleaved]: improve on the Contiguous partiioning, make
    threads accessing consecutive elements.
  - Interleaved loses on a cold L2. [Nsight Compute][ncu] on H100,
    gutenberg-english (21.6 MB), 2643 blocks × 256 threads, `cFactor = 32`,
    L2 flushed:

    | Metric                          | Contiguous | Interleaved |
    | ------------------------------- | ---------: | ----------: |
    | Duration                        |    31.7 µs |     43.4 µs |
    | DRAM read                       |    21.7 MB |     21.7 MB |
    | DRAM throughput                 |      20.4% |       15.0% |
    | L1 global load requests         |    676,608 |     676,596 |
    | L1 sectors per request          |         32 |           1 |
    | L1 sector hit rate              |      96.7% |          0% |
    | L1 throughput                   |      93.3% |       13.3% |
    | L2 read requests                |    170,845 |     420,979 |
    | Long scoreboard stall per issue |   17.2 cyc |    34.2 cyc |
    | Cycles with no eligible warp    |      52.2% |       68.2% |

    - Both kernels read the same bytes, so coalescing does not cut DRAM
      traffic. A byte loaded once costs the same either way.
    - Each iteration is `LDG` → `ATOMS`, and the `i < n` branch stops the
      compiler from hoisting later loads. A warp keeps one load in flight.
    - Contiguous: lanes sit 32 B apart, so the first load of a warp spans 32
      sectors (1 KB, 8 lines). That one DRAM round trip fills L1 for the next
      31 iterations, hence the 96.7% hit rate.
    - Interleaved: each load fetches one fresh 32 B sector, so every iteration
      waits a full DRAM round trip. Long scoreboard stalls double.
    - By [Little's law][little], bandwidth = bytes in flight / latency.
      Interleaved keeps about 32× fewer bytes in flight per warp, so DRAM
      stays at 15%.
    - With a warm L2 the latency shrinks and contiguous pays for its 32-sector
      requests in L1 (93% busy), so interleaved wins the batch run.
    - The grid-stride loop (Fig. 9.14) compiles to the same `LDG` → `ATOMS`
      chain, so it does not help.
    - Fix: put more bytes in flight per warp. Load all `cFactor` elements
      before any atomics, or load `uchar4`/`uint4` per thread.

[ncu]: https://docs.nvidia.com/nsight-compute/ProfilingGuide/index.html
[little]: https://en.wikipedia.org/wiki/Little%27s_law
