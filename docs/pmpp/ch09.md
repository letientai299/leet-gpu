- [x] 9.3 Latency and throughput of atomic operations
  - Modern GPUs support atomic operations in the last level cache, e.g. L2.
    The atomic operation read-modify-write mark the relevant L2 cache line
    dirty. That line will be written back to DRAM sometime later.

- [x] 9.5 Coarsening
  - [Contiguous][hist_contiguous]: simple, intuitive, but, sub optimal GMEM
    access pattern, because each thread access elements far away from each
    other.
  - [Interleaved][hist_interleaved]: improve on the Contiguous partiioning, make
    threads accessing consecutive elements.
  - Interleaved loses on a cold L2. [Nsight Compute][ncu] on H100,
    gutenberg-english (21.6 MB), 2643 blocks × 256 threads, `cFactor = 32`,
    L2 flushed, SM clock locked to 1350 MHz as in `mise cmp` (ncu
    `--clock-control none`). Duration is GPU kernel time and excludes event
    overhead:

    | Metric                          | Contiguous | Interleaved |       v2 |
    | ------------------------------- | ---------: | ----------: | -------: |
    | Duration                        |    43.6 µs |     52.1 µs |  24.1 µs |
    | DRAM read                       |    21.7 MB |     21.7 MB |  21.7 MB |
    | DRAM throughput                 |      14.8% |       12.5% |    26.9% |
    | L1 global load requests         |    676,608 |     676,596 |  676,596 |
    | L1 sectors per request          |         32 |           1 |        1 |
    | L1 sector hit rate              |      96.9% |          0% |       0% |
    | L1 throughput                   |      94.6% |       16.4% |    38.4% |
    | L2 read requests                |    172,517 |     433,440 |  608,974 |
    | Long scoreboard stall per issue |   16.7 cyc |    26.5 cyc |  0.6 cyc |
    | Cycles with no eligible warp    |      51.5% |       61.2% |    15.2% |
    | Registers per thread            |         16 |          16 |       40 |
    | Theoretical occupancy           |       100% |        100% |      75% |
    | Achieved occupancy              |      89.8% |       83.5% |    66.0% |

    - All three kernels read the same 21.7 MB from DRAM, so coalescing does
      not cut DRAM traffic. They differ in how they wait for it.
    - Contiguous and interleaved run `LDG` → `ATOMS` per iteration, and the
      `i < n` branch stops the compiler from hoisting later loads. A warp
      keeps one load instruction in flight.
    - Contiguous: lanes sit 32 B apart, so the first load of a warp spans 32
      sectors (1 KB, 8 lines). That one DRAM round trip fills L1 for the next
      31 iterations, hence the 96.9% hit rate. The cost moves to L1: every
      request looks up 32 sectors, 21.7 M in total, and L1 runs at 94.6%.
    - Interleaved: each load fetches one fresh 32 B sector, so every iteration
      waits a full DRAM round trip. Long scoreboard stalls rise 1.6×.
    - By [Little's law][little], bandwidth = bytes in flight / latency.
      Interleaved keeps about 32× fewer bytes in flight per warp than
      contiguous, so DRAM stays at 12.5%. Contiguous is L1 bound, not DRAM
      bound, at 14.8%.
    - With a warm L2 the round trip shrinks, interleaved's latency penalty
      fades, and contiguous's L1 cost dominates, so interleaved wins the
      batch run.
    - The grid-stride loop (Fig. 9.14) compiles to the same `LDG` → `ATOMS`
      chain, so it does not help.
    - Fix: put more bytes in flight per warp without the L1 cost. v2 below
      does this.
  - [Interleaved v2][hist_interleaved_v2]: split the loop. Load all `cFactor`
    chars into registers, then run the atomics.
    - nvcc fully unrolls the constant-trip load loop on its own: 32
      predicated `LDG` back to back, then 32 `ATOMS`. `chars` stays in
      registers, with no local memory.
    - Each warp keeps 32 loads in flight and waits about one DRAM round trip
      per thread. Long scoreboard stalls drop from 26.5 to 0.6 cycles per
      issue, and DRAM throughput rises to 26.9%.
    - Cost: 40 registers per thread caps a SM at 6 blocks (48 of 64 warps,
      75% theoretical, 66% achieved). Full occupancy needs ≤ 32 registers.
      Each warp now hides its own latency, so fewer warps still win.
    - `mise cmp` at 1350 MHz: cold 27.1 µs vs 48.3 µs contiguous and 58.9 µs
      interleaved; batch 24.3 µs vs 44.2 µs and 32.1 µs.

Questions transcribed from the book.

## Ex 9.1

Assume that each atomic operation in a DRAM system has a total latency of
$100\ \mathrm{ns}$. What is the maximum throughput that we can get for atomic
operations on the same global memory variable?

**Answer:** $1s/10ns = 10^7 => 10M op/s = 0.01G op/s$

## Ex 9.2

For a processor that supports atomic operations in L2 cache, assume that each
atomic operation takes $4\ \mathrm{ns}$ to complete in L2 cache and
$100\ \mathrm{ns}$ to complete in DRAM. Assume that $90$% of the atomic
operations hit in L2 cache. What is the approximate throughput for atomic
operations on the same global memory variable?

**Answer:** The average latency is 0.9 × 4 ns + 0.1 × 100 ns = 13.6 ns. Atomic
operations on the same variable serialize, so the approximate throughput is 1 /
(13.6 × 10⁻⁹ s) ≈ 73.5 million atomic operations/s.

## Ex 9.3

In [Ex 9.1][ex-9-1], assume that a kernel performs five floating-point
operations per atomic operation. What is the maximum floating-point throughput
of the kernel execution as limited by the throughput of the atomic operations?

**Answer:** 0.05G op/s

## Ex 9.4

In [Ex 9.1][ex-9-1], assume that we privatize the global memory variable into
shared memory variables in the kernel and that the shared memory access latency
is $1\ \mathrm{ns}$. All original global memory atomic operations are converted
into shared memory atomic operation. For simplicity, assume that the additional
global memory atomic operations for accumulating privatized variable into the
global variable adds $10$% to the total execution time. Assume that a kernel
performs five floating-point operations per atomic operation. What is the
maximum floating-point throughput of the kernel execution as limited by the
throughput of the atomic operations?

**Answer:** 100 ns/aop (aop is atomic op) to GMEM allow 0.01G aop/s. Moving to
SMEM, with 1 ns/op, we get 1G aop/s. We do 5 FLOP/aop, so, the throughput is 5G
FLOP/s. But, we need to pay for 10% time to move data from SMEM to GMEM, thus,
actual throughput would be $5G / 1.1 = 4.545G$ FLOP/s.

## Ex 9.5

To perform an atomic add operation to add the value of an integer variable
`Partial` to a global memory integer variable `Total`, which one of the
following statements should be used?

- a. `atomicAdd(Total, 1);`
- b. `atomicAdd(&Total, &Partial);`
- c. `atomicAdd(Total, &Partial);`
- d. `atomicAdd(&Total, Partial);`

**Answer:** d

## Ex 9.6

Consider a histogram kernel that processes an input with $524{,}288$ elements
to produce a histogram with $128$ bins. The kernel is configured with $1024$
threads per block.

- a. What is the total number of atomic operations that are performed on global
  memory by the kernel in Fig. 9.6 where no privatization, shared memory, and
  thread coarsening are used?
- b. What is the maximum number of atomic operations that may be performed on
  global memory by the kernel in Fig. 9.10 where privatization and shared
  memory are used but not thread coarsening?
- c. What is the maximum number of atomic operations that may be performed on
  global memory by the kernel in Fig. 9.14 where privatization, shared memory,
  and thread coarsening are used with a coarsening factor of $4$?

**Answer:**

- a. 524288 atomic operations. Each thread need 1 op.
- b. $524288 / 1024 = 512$ blocks, thus, need $512*128 = 65536$ atomic op to
  update global mem.
- c. With coarsening factor 4, we need $524288/4 = 131072$ threads, or 128
  blocks, yielding $128 \times 128 = 16384$ global mem atomic op.
