# Optimizations strategies

- **Maximizing occupancy**: tune threads per block, shared mem per block, and
  register per thread.
  - Compute: hide pipeline latency
  - Mem: hide DRAM latency
- **Coalescence GMEM**: rearrange mapping of threads to data and data layout,
  move data from GMEM to SMEM in batch and make threads work with SMEM.
  - **[Corner turning][corner-turning]**: load a tile into SMEM with coalesced
    GMEM accesses, synchronize, then read it along another dimension. Pad the
    SMEM tile when needed to avoid bank conflicts.
  - Compute: fewer pipeline stalls waiting for data
  - Mem: Less GMEM traffic, utilize more bursts and cache lines.
- **Minimizing control divergence**: rearrange mapping of threads to work/data,
  or change data layout.
  - Compute: High SIMD efficiency, fewer idle cores
- **Tiling**: make all threads in block load and reuse the same data in SMEM.
  - Compute: fewer pipeline stalls waiting for GMEM.
  - Mem: less GMEM traffic
- **Privatization**: apply partial updates to a private copy of the data and
  then updating the universal copy when done
  - Compute: Fewer pipeline stalls
  - Mem: Less contention and serialization of atomic updates
- **Thread coarsening**: assign multiple units of parallelism to each thread.
  - Compute: less redundant work, divergence or sync
  - Mem: less traffic.

[corner-turning]: https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/writing-cuda-kernels.html#matrix-transpose-example-using-shared-memory
