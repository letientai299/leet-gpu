## Reading notes

- [x] 6.1 Memory coalescing
  - [`../../src/pmpp/ch06/matmul.corner.cpp`][ch06-matmul-corner]
  - Mem coalescing + tiling: help reach potential perf by utilize global mem
    bandwidth efficiently
  - DRAM is slow compare to CPU clock cycles. Throughput is increase by
    providing more data per reading instead of reducing per-cell access latency.
  - **DRAM burst**: Each time a DRAM location is accessed, a range of
    consecutive locations including the requested one are accessed.
  - _The most favorable access pattern_ is **all threads in a warp** access
    consecutive global memory locations. Hardware could then **coalesces**,
    enable DRAM burst.
  - Strategies:
    - Rearrange how threads are mapped to the data.
    - Rearrange the layout of the data.
    - Transfer data from GMEM (DRAM) to SMEM (SRAM) first: **corner turning**.
  - SRAM: static RAM, used for shared-mem, fast, more expensive.
  - DRAM: dynamic RAM, global mem, denser, cheaper.

- [x] 6.2 Hiding memory latency
  - **Hiding latency** means doing more work, keeping the execution units busy
    while waiting for a memory request completes. Requests aren't done faster.
  - DRAM physical:
    - **Bank**: an independently operated DRAM storage array. Requests to
      different banks can overlap.
    - **Channel**: an independently controlled path between a memory controller
      and a group of DRAM devices. Multiple channels can transfer data in
      parallel. A channel connect to multiple banks via a **bus**.
    - **Bus**: the wires that carry addresses, commands, and data. Data-bus
      width and transfer rate determine the channel's peak bandwidth.
    - Address interleaving spreads requests across banks and channels. Enough
      independent outstanding requests keep them busy and hide each request's
      latency behind other transfers.
  - A warp stalls when its next instruction depends on an outstanding global
    memory access.
  - The SM hides this latency by issuing instructions from another ready,
    resident warp. Warp state remains on-chip, so switching warps has no
    context-switch overhead.
  - More resident warps provide more chances to find useful work while other
    warps wait for memory.
  - Registers, shared memory, threads, and block slots limit the numbesm cost.
    resident warps. The grid must also contain enough blocks to occupy the SMs.
  - High occupancy does not guarantee high performance. It only increases the
    capacity to hide latency; the SM still needs ready warps and useful work.

- [x] 6.3 Thread coarsening
  - [`../../src/pmpp/ch06/matmul.coarse.cpp`][ch06-matmul-coarse]
  - Benchmark results [`./ch06.bench.md`](ch06.bench.md)
  - Parallelizing work at the finest granularity disadvantage:
    - Redundant data loading
    - Redundant work
    - sync overhead
  - **Thread coarsening**: assign multiple units of work to a thread, partially
    serialize the work and reduce the parallelism cost.
    - Don't use it unnecessarily
    - Use it carefully to not hurt resource utilization and occupancy.
    - Best coarsening factor is _device and dataset specific_

### Ex 6.2

For tiled matrix multiplication, of the possible range of values for
`BLOCK_SIZE`, for what values of `BLOCK_SIZE` will the kernel completely avoid
uncoalesced accesses to global memory? (You need to consider only square
blocks.)

**Answer:** 32, exactly the warp limit of all current GPUs. `BLOCK_SIZE` smaller
than 32 cause the warp cross the boundary and uncoalesced. 64 would also
coalesced, but 64x64 is bigger than max 1024 threads/block, thus, doesn't work.

### Ex 6.3

```c:line-numbers {5,7,10,11}
__global__ void foo_kernel(float* a, float* b, float* c, float* d, float* e) {
  unsigned int i = blockIdx.x * blockDim.x + threadIdx.x;
  __shared__ float a_s[256];
  __shared__ float bc_s[4 * 256];

}
```

### Ex 6.4

What is the floating point to global memory access ratio (in OP/B) of each of
the following matrix-matrix multiplication kernels?

- a. The simple kernel described in Chapter 3, Multidimensional Grids and Data,
  without any optimizations applied.
- b. The kernel described in Chapter 5, Memory Architecture and Data Locality,
  with shared memory tiling applied using a tile size of $32 \times 32$.
- c. The kernel described in this chapter with shared memory tiling applied
  using a tile size of $32 \times 32$ and thread coarsening applied using a
  coarsening factor of $4$.

**Answer:**

- a. 0.25 OP/B
- b. Each threads load 4 bytes from GMEM to SMEM for A and B, and thus, total
  traffic is 8B. With the book tile size 32, each threads do 32 multiplication
  and 32 additions, thus, 64 FLOPs. The ratio is therefore 8 OP/B.
- c. With coarse factor 4, each kernel now use the same 4 bytes of A and 4x4
  bytes of B to produce 4 outputs. Thus, total bytes traffic is $4+4x4 = 20$,
  and total FLOP is $4 * 2 * 32 = 256$. So, the ratio is $256/20 = 12.8$ OP/B
