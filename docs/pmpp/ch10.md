## Reading Notes

- [x] 10.1 Background
  - _Mathematically_, a reduction can be defined for a set of items based on a
    _binary operator_ if the operator has a _well-defined identity_ value.
    The identity allow the operation to support empty set and unused positions.
  - This is basically the `reduce(init, op, items[])` pattern. Also looks like a
    histogram with 1 bin.
  - To parallel this, I guess we need multi phases thread coarsening:
    - Phase 1: Each thread handle a slice of the input.
    - Phase 2: When all threads in a block done, only 1 thread combine the
      partial results into one result per block.
    - Phase 3: All thread of all blocks stop, except 1 thread in the whole
      grid combine all block level results.
- [x] 10.2 Reduction trees
  - The book give an idea to reduce in parallel like a reversed binary tree.
- [x] 10.3 A simple reduction kernel
  - [`reduce_basic`][reduce-basic]: simple binary tree reduction kernel, very
    high divergence (haft of the threads become inactive after each round).
- [x] 10.4 Minimizing control divergence
  - Only about 35% of the hardware’s potential to speed up the computation for
    input of 256 elements.
  - [`reduce_convergent`][reduce-convergent]: move the usable elements in later
    rounds near each other, thus, allow discarding complete inactive warps.
  - The efficiency is $255/384=66$%, almost double the basic kernel.
- [x] 10.5 Minimizing memory divergence
  - No new kernel here. This section discuss about memory coalescing benefit of
    the `reduce.convergent` kernel, which is quite apparent based on the book
    illustration.
- [x] 10.6 Minimizing global memory accesses
  - [`reduce_shared`][reduce-shared]: use shared mem to copy half of the input,
    still only works under the small input scale, one single block so that
    `__syncthreads()` works for all thread.
- [x] 10.7 Hierarchical reduction for arbitrary input length
  - [`reduce_hierarchical`][reduce-hierarchical]: get rid of the `__syncthreads`
    single block limit by partition (or tiling), each block works on a
    partition, then, use `atomicAdd` to combine the results.
- [x] 10.8 Thread coarsening for reduced overhead
  - [`reduce_coarse`][reduce-coarse]
- [x] 10.9 Summary

## Ex 10.1

For the simple reduction kernel in Fig. 10.6, if the number of elements is
$1024$ and the warp size is $32$, how many warps in the block will have
divergence during the fifth iteration?

**Answer:** $1024/2 = 512$ threads, thus 16 warps. The `stride` at 5th iteration
is 16. Each warps has 32 threads, from 0-31. So, only thread 0 and thread 16 is
active. The remaining 30 threads in each warp is inactive. All 16 warps have
divergence.

## Ex 10.2

For the improved reduction kernel in Fig. 10.9, if the number of elements is
$1024$ and the warp size is $32$, how many warps will have divergence during
the fifth iteration?

**Answer:** No wapr has divergence. Only 1 warp whose `threadIdx.x < 32` remains
active, and it doesn't have divergence.
