## Reading notes

Stencil vs Convolution:

- **Origin**: stencil comes from sciencetific computing. Convolution come from
  image processing, which is itself a special form of stencil.
- **Similarity**: calc new value from current value of same position, its
  neighbors and the filter. Deal with halo and ghost cells.
- **Difference**:
  - stencil updates the same grid iteratively. (TODO: vet)
  - calculations might have dependences and ordering constraints
  - often use high precision, thus, consume more on-chip mem.

- [x] 8.3 Shared memory tiling for stencil sweep
  - [Tiled][stencil_tile]
  -

   For 5 points stencil (order 1), with ouput tile size $T$. Thus, input tile
   size is $T+2$. We don't use the corner points, so, we need to load
   $4\times((T+2)^2 - 4)$ bytes. For each of the $T^2$ output points, we do 5
   multiplications and 4 additions. So, total float ops is $9T^2$. Ratio is

    ```math
    \frac{9T^2}{4((T+2)^2 - 4)} = 2.25 \frac{T^2}{(T+2)^2 - 4}
    ```

   > for a 2D five-point stencil, the upper bound on the ratio is only 2.5 OP/B

   - 9 points stencil (order 2), from the book, is 4.5 OP/B (convo get 12.5).
   - 15 points, 6.5 OP/B (convo 24.5 OP/B).

     So, it's 2.25 in my convention. The book uses 5 mul, 5 add, thus, 2.5.
