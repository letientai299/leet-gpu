## Reading notes

Stencil vs Convolution:

- **Origin**: stencil comes from sciencetific computing. Convolution come from
  image processing, which is itself a special form of stencil.
- **Similarity**: calc new value from current value of same position, its
  neighbors and the filter. Deal with halo and ghost cells.
- **Difference**:
  - stencil sweeps repeat over the same grid; the output buffer becomes the
    next input. Boundary cells keep their values.
  - calculations might have dependences and ordering constraints
  - often use high precision, thus, consume more on-chip mem.

- [x] 8.3 Shared memory tiling for stencil sweep
  - For 5 points stencil (order 1), with ouput tile size $T$. Thus, input tile
    size is $T+2$. We don't use the corner points, so, we need to load
    $4\times((T+2)^2 - 4)$ bytes. For each of the $T^2$ output points, we do 5
    multiplications and 4 additions. So, total float ops is $9T^2$. Ratio is

    ```math
    \frac{9T^2}{4((T+2)^2 - 4)} = 2.25 \frac{T^2}{(T+2)^2 - 4}
    ```

    So, it's 2.25 in my convention. The book uses 5 mul, 5 add, thus, 2.5.
  - 9 points stencil (order 2), from the book, is 4.5 OP/B (convo get 12.5).
  - 15 points, 6.5 OP/B (convo 24.5 OP/B).
  - [Tiled][stencil_tile] kernel code. Rough estimation is 1 float, thus, 4B;
    and, do 13 OP. So, the ration is bound $<= 13/4 = 5.25$. In practice, the
    tile size $T$ is small, because we need $T^3$ threads. 2 big disadvantages:
    - Input tile is $8^3$, output tile $6^3$, thus, wasted 58% input elements as
      halo, limit the reuse ration and compute to mem access ratio.
    - Small practice tile size mean worse mem coalescing, thus, waste mem
      bandwidth.

[stencil_tile]: ../../src/pmpp/ch08/stencil.tile.cu

- [x] 8.4 Thread coarsening
  - [Thread-coarsened scaffold][stencil_coarsen]
  - Intentionally, partially serialize parallel units, to minimize the cost of
    parallelism. In the stencil case, it's the block size limit, and low data
    reuse due to high halo elements count.
  - This section started after we understood why basic tiling doesn't work for
    stencil patterns. Cool!

- [x] 8.5 Register tiling
  - [Register-tiled scaffold][stencil_register]
  - Use register (local var) for the z-axis element instead of SMEM, thus,
    reduce the cost of SMEM and improve perf a bit (accessing register is faster
    than SMEM).
  - Doesn't reduce GMEM bandwidth, though.

## Ex 8.1

Consider a 3D stencil computation on a grid of size $120 \times 120 \times 120$,
including boundary cells.

- a. What is the number of output grid points that is computed during each
  stencil sweep?
- b. For the basic kernel in Fig. 8.6, what is the number of thread blocks that
  are needed, assuming a block size of $8 \times 8 \times 8$?
- c. For the kernel with shared memory tiling in Fig. 8.8, what is the number
  of thread blocks that are needed, assuming a block size of
  $8 \times 8 \times 8$?
- d. For the kernel with shared memory tiling and thread coarsening in
  Fig. 8.10, what is the number of thread blocks that are needed, assuming a
  block size of $32 \times 32$?

**Answer:**

- a. $(120-2r)^3$ output points, where $r$ is the stencil order.
- b. $\lceil120/8\rceil^3 = 15^3 = 3375$ thread blocks.
- c. $\lceil120/6\rceil^3 = 20^3 = 8000$ thread blocks.
- d. $\lceil120/30\rceil^3 = 4^3 = 64$ thread blocks.

## Ex 8.2

Consider an implementation of a seven-point (3D) stencil with shared memory
tiling and thread coarsening applied. The implementation is similar to those in
Figs. 8.10 and 8.12, except that the tiles are not perfect cubes. Instead, a
thread block size of $32 \times 32$ is used as well as a coarsening factor of
$16$ (i.e., each thread block processes $16$ consecutive output planes in the
$z$ dimension).

- a. What is the size of the input tile (in number of elements) that the thread
  block loads throughout its lifetime?
- b. What is the size of the output tile (in number of elements) that the
  thread block processes throughout its lifetime?
- c. What is the floating point to global memory access ratio (in
  $\mathrm{OP/B}$) of the kernel?
- d. How much shared memory (in bytes) is needed by each thread block if
  register tiling is not used, as in Fig. 8.10?
- e. How much shared memory (in bytes) is needed by each thread block if
  register tiling is used, as in Fig. 8.12?

**Answer:**

- a. $32 * 32 * (16+2) = 18{,}432$ elements.
- b. $30 * 30 * 16 = 14{,}400$ elements.
- c. $13 \times 14{,}400/(4 \times 18{,}432) \approx 2.54\ \mathrm{OP/B}$.
- d. $32 * 32 * 3 * 4 = 3072 * 4 = 12{,}288$ B
- e. $32 * 32 * 4 = 1024 * 4 = 4096$ B
